CLUPrimitives.lean (four fixes):

CLU_bits_approx: replaced three unresolved sorries with a closed proof.
Strategy: reduce CLU_bits in (3.321, 3.323) to integer comparisons
2^3321 < 10^1000 and 10^1000 < 2^3323 (both verified by native_decide),
then carry through Real.log_lt_log + Real.log_pow + push_cast + linarith.
The reduction works because 3321 * log_10(2) ≈ 999.72 and
3323 * log_10(2) ≈ 1000.32, bracketing 10^1000 on both sides.
Previous attempt used norm_num [Real.exp_le_exp] which cannot evaluate
transcendental bounds; the native_decide path compiles to native integer
arithmetic and handles ~1000-digit comparisons without issue.

CLU_scale_independence: replaced incomplete dangling-have proof with:
  unfold CLU; congr 1; have hcx := mul_ne_zero hc.ne' hx.ne'; field_simp [hcx]
Previous proof ended mid-tactic with an unused `have : Real.exp (Real.log 10) = 10`
that never discharged the goal. congr 1 reduces to the arithmetic subgoal
(10 * c * x) / (c * x) = 10 which field_simp closes directly.

Section V.4 and V.5 comment syntax: changed four // lines to --.
C-style // comments are not valid in Lean 4; silently ignored by the parser
but would cause issues under strict linting. Affected: the grokking transition
description (V.4) and the log-normal/criticality description (V.5), including
the section-close // ===... delimiter in V.5.
